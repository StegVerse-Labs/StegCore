# Phantom Trust

Phantom trust is a failure condition in which a system, actor, or credential
remains technically valid and policy-authorized while no longer being
semantically legitimate in context.

Phantom trust is silent by default.

## Characteristics of Phantom Trust

Phantom trust typically exhibits the following properties:
- No authentication failure
- No authorization violation
- No policy breach
- No exploit or intrusion

Despite this, continued action is no longer trustworthy.

## Common Phantom Trust States

Examples include:
- Orphaned automation operating without accountable owners
- Credentials valid beyond their original operational assumptions
- Context drift where environment or purpose has changed
- Temporal desynchronization between state and action
- Cross-custody access without explicit transfer

These states evade traditional security models.

## Why Phantom Trust Matters

Phantom trust explains why systems can:
- Pass audits
- Operate “correctly”
- Avoid alerts

…and still behave illegitimately at scale.

BCAT exists to surface and govern phantom trust before it produces harm.

Phantom trust is not malicious intent.
It is trust without continuity.
