# Operational Truth Boundaries

Operational truth boundaries define the conditions under which an action
remains valid with respect to system state, context, continuity, and accountability.

They distinguish local correctness from global legitimacy.

## Local Correctness vs Operational Truth

An action may be locally correct:
- Inputs valid
- Logic sound
- Output acceptable

Yet still violate operational truth if:
- Context assumptions no longer hold
- Trust continuity has degraded
- Authority has decayed

BCAT evaluates operational truth, not just correctness.

## Boundary Pressure and Degradation

Operational truth boundaries are diagnostic, not punitive.

Approaching or stressing a boundary may:
- Reduce autonomy
- Trigger safeguards
- Require confirmation
- Initiate graceful degradation

Boundary violations need not cause failure.
They may instead prevent it.

## Why Boundaries Must Be Explicit

Implicit boundaries are invisible.
Invisible boundaries cannot be governed.

BCAT requires operational truth boundaries to be:
- Explicit
- Inspectable
- Auditable
- Revisable

Only explicit boundaries enable trust at scale.
