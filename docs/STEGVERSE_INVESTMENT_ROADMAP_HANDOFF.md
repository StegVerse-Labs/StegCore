## Marketplace Strategy

### Do Not Build Marketplace First

Reason:

```text
Supply without demand creates a dead marketplace. Demand-side repeat usage must exist first.
```

### Phase Order

```text
Phase A: Centralized orchestration using rented compute.
Phase B: Curated compute contributors.
Phase C: Open compute marketplace.
```

### Role of StegVerse

```text
StegVerse should control verification, receipts, routing, reputation, and admissibility.
It should avoid owning all compute unless required for guarantees or margins.
```

## Token Strategy

Current recommendation:

```text
No token in Phase 1 or Phase 2.
```

Rationale:

```text
1. USD revenue is simpler and investor-friendly.
2. Token mechanics before real demand add regulatory and narrative complexity.
3. The marketplace can later use token mechanics only if contributor incentives require it.
```

Token consideration trigger:

```text
Revisit token economics only after recurring demand, repeatable verification workflows, and contributor-side compute participation are proven.
```
